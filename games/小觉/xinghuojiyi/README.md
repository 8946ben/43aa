# 星火机忆 · Spark Engine

> A-SOUL 同人星图策略小游戏（纯静态 HTML5，零依赖、零构建、零联网）。
> 双击 `index.html` 即可游玩，也可以从大厅点进来。

---

## 一句话玩法

**你只有一颗会走的火种：点亮相邻的星图节点，让链路接回核心——供给、火力、护盾，每颗灯都要取舍，撑过三波机群。**

---

## 这个游戏和常见的「塔防」差在哪

现有的 `guardTour_td`（保卫萝卜式）是**敌人沿固定路线走、你在路边建塔**。
《星火机忆》做成一张**无向图**，核心变化有三点：

| | 保卫萝卜式塔防 | 星火机忆 |
|---|---|---|
| 空间 | 敌人走固定路径，塔建在路旁空地 | 敌人从核心外围自由飞入，节点构成一张可走的网 |
| 建造 | 每个塔独立花钱，互不影响 | **火种只能移动一格**：点亮的每一颗，必须是上一颗的相邻节点 |
| 胜负手 | 塔的覆盖与等级 | **链路**：从核心出发、只经过已点亮节点能走通，节点才工作 |

于是"先修路还是先修炮"变成了核心决策：把一个孤岛点亮是浪费，
但把核心周围铺满又会挤掉补给线。**被啃掉的一颗节点会把整条支线断电**，
这是本作最紧张的一刻。

## 玩法说明

### 节点与链路

场上有 14 颗节点，围绕核心分三环（内环 4 / 中环 5 / 外环 5）。

- **点亮**：火种停在某一颗上时，点击与之**吸附相连**（虚线高亮）的节点即可点亮，花费星尘。
  第一次点落时火种还没落地，任意节点都可以当起点。
- **链路**：从核心出发，沿**已点亮**的节点能走通，才算"接上电"。
  没接上的节点是孤岛 —— 不产星尘、不开火、不加盾。
- 核心只与内环相连，内外环之间不会横穿核心 —— 你天然要对着一圈防线做取舍。

### 四种节点

| 节点 | 造价 | 作用 | 注意 |
|---|---|---|---|
| **星尘源** | 3 尘 | 每秒产 2.0 星尘 | 唯一的货币来源，断了就点不动任何东西 |
| **生产器** | 3 尘 | 每秒产 2.2 燃料 | 燃料见底 → **全场变暗停产** |
| **火力** | 4 尘 | 自动索敌射击（30 DPS / 190 射程） | 必须接通才开火 |
| **护盾** | 4 尘 | 给核心加盾（上限 30）并缓慢回血 | 必须接通才生效 |

**扩张惩罚**：点亮的节点越多，单颗星尘源的效率越低（最低 45%），
维持星图每 tick 的燃料消耗也越高。铺满全图不是最优解。

### 机群与波次

| 机群 | 血量 | 特点 |
|---|---|---|
| 飘虫 | 32 | 慢速直冲核心，成群 |
| **啃食者** | 58 | **优先扑向节点啃灯**，会把节点啃灭（复燃要额外花钱） |
| 侵蚀体 | 180 | 血厚慢速，直奔核心 |

- 共 **3 波**，一波比一波密（生成间隔 560ms → 380ms，敌人权重上调）。
- 波与波之间有 30 秒喘息，可以铺星图。
- 撑过第 3 波、核心没破即胜利；核心血量决定 1~3 星。

### 遗物

每次首次点亮节点有 22% 概率掉落遗物，**即时生效**，可以滚雪球：

| 遗物 | 效果 |
|---|---|
| 折射棱镜 | 火力伤害 +15% |
| 超频齿轮 | 火力射速 +20% |
| 丰饶之种 | 星尘产出 +25% |
| 冷凝环 | 燃料产出 +25% |
| 远望之瞳 | 火力射程 +18% |
| 蓄能池 | 全场节点生命 +20% |
| 星火之种 | 立即 +3 星尘 +6 燃料 |

| 操作 | 效果 |
|---|---|
| **点击 / 轻触节点** | 点亮该节点（需相邻且星尘足够） |

## 平衡性验证（怎么调出来的）

因为没有浏览器可用，我把游戏逻辑做成**可以在 Node 里无头运行**的：
`tools/harness.js` 提供一套极简的假 DOM / 假 canvas，
于是 `js/game.js` 能被真正跑起来，机器人可以真的打完一整局。

| 文件 | 作用 |
|---|---|
| `tools/harness.js` | 假 DOM + 假 canvas，把 `data.js` / `graph.js` / `game.js` 跑在 Node 里 |
| `tools/balance.js` | 机器人玩家（均衡 / 经济 / 龟缩 / 随机四种打法），跑蒙特卡洛 |
| `tools/verify.js` | 冒烟测试：能启动、能出菜单、HUD 正常 |

```bash
node tools/verify.js              # 冒烟
node tools/balance.js 4           # 每种策略 × 星图各 4 局
```

**这套无头测试抓到过 4 个会在浏览器里直接爆炸的 bug**，都能写进 commit 记录里：

1. `banner is not defined` —— 波次横幅忘了写，第一波开始就抛异常，游戏卡死。
2. 星图连边规则不一致：`graph.js` 里内环节点互相禁止相连，导致**点亮第一颗后火种再也走不出去**，整局必死。
3. 节点身份混用：代码里把 `n.i`（字符串 `"n0"`）当成数组下标用，`canLight` 永远返回 false。
4. 开局内环只随机出 1 颗星尘源 —— 点亮 3 颗后星尘断供，**整张图成死局**（现在保证内环有 2 星尘源 + 1 生产器 + 1 火力）。

最终平衡（每格 4 局，机器人策略）：

| 用当前数值 | 胜率区间 |
|---|---|
| 均衡 / 经济 / 龟缩 / 随机 | 33% – 100%，取决于种子与打法 |
| 典型「乱点」玩家 | 约 25%~50%，必须理解链路才能稳赢 |
| 全部对局 | 0 脚本报错，0 卡死 |

## 技术说明

- 内部分辨率 960×640，`devicePixelRatio` 上限 2；CSS 按 3:2 等比缩放，指针坐标用 `getBoundingClientRect()` 换算。
- 经典 `<script>` 顺序引入（`data.js` → `graph.js` → `game.js`），**无 ES Module / fetch / Worker / CDN**，`file://` 直接可玩。
- `requestAnimationFrame` + `dt` 驱动，dt 上限 0.05s 防止切标签后跳帧。
- 全部画面（星野、节点、机群、弹道、粒子）为 canvas 矢量实时绘制；**零图片素材**。
- 音效为 WebAudio 振荡器 / 白噪声实时合成（点亮、开火、啃食、漏怪、波次、遗物、胜负），同名音效带节流，避免炸耳机。
- 最高分存 `localStorage`，键名 `xinghuo_best_v1`。
- 最坏情况（14 节点全亮 + 108 敌人）实测 **0.38ms/帧**，手机也有余量。

## 设计笔记（做给自己看的）

想做的其实是「**星图经营**」而不是「塔防」：
一个人守着一张会熄灭的星图，点亮像是给星星起名字。

最后落成的三个取舍：
1. **火种只能走一格** —— 让"扩张"变成有代价的连笔，而不是无限点击。
2. **啃食者会啃灯** —— 这是唯一能打断你节奏的东西，也是我最满意的机制：
   你铺得越长，越怕它咬断中间那盏。
3. **三张星图共用同一张种子** —— 这样选星图真的是选流派，而不是选运气。

留待 v0.2 的想法：节点升级、可解锁的第四类「回声」节点、每日固定种子挑战。
